# NestJS Starter

Backend starter: NestJS 11 + Prisma 7 + PostgreSQL 18 (Docker).

## Stack

- **Framework**: NestJS 11 (Express), TypeScript strict
- **Database**: PostgreSQL 18 in docker-compose (DB only; the app runs locally)
- **ORM / migrations**: Prisma 7 (`prisma migrate`), driver adapter `@prisma/adapter-pg`
- **Configuration**: `@nestjs/config` + Joi env validation
- **Request validation**: global `ValidationPipe` + class-validator
- **Health**: `@nestjs/terminus` — `GET /api/v1/health` (with DB ping)
- **Docs**: Swagger UI at `/api/docs`
- **Tests**: Jest (unit + e2e)

## Requirements

- **Node.js 22 LTS** (`.nvmrc` included — `nvm use`). ⚠️ Node 23 is not supported by Prisma 7
- Docker (colima/Docker Desktop)

## Quick Start

```bash
nvm use                # Node 22
npm install            # postinstall generates the Prisma client
cp .env.example .env   # on first run — app works without TimeTracker keys; see Seed data below
npm run db:up          # start Postgres in Docker
npm run db:migrate     # apply migrations (also runs the seed automatically)
npm run start:dev      # http://localhost:3001
```

Check: `curl http://localhost:3001/api/v1/health`

### Seed data

`TIMETRACKER_ACCOUNTING_API_KEY` and `TIMETRACKER_TALENTS_API_KEY` (contact the
TimeTracker team for values; `TIMETRACKER_BASE_URL` already has a working
default) must be set in `.env` before seeding — the seed script imports the
identity population (id/email/name/hash/countryCode) from the TimeTracker
external API and layers synthetic grade/position/department/employment-type
history on top. It's idempotent: rerunning against an already-seeded DB
updates existing rows in place rather than duplicating them.

- `npm run db:migrate` runs it automatically after applying pending migrations
- `npm run db:seed` runs it directly (also what `postbuild` chains after `prisma migrate deploy` for auto-deploy)

**No TimeTracker access yet?** You're not stuck. The two keys ship
commented-out in `.env.example` and are optional at the config-validation
level, so `npm run start:dev` and normal app usage (including tests) work
completely fine without them. `npm run db:migrate` only auto-seeds when it
actually applies a *new* pending migration — if your schema is already up to
date (the common case once you've migrated once), it just prints "Already in
sync" and does nothing seed-related. Only an explicit `npm run db:seed`, or a
`db:migrate` that happens to apply a real pending migration, invokes the seed
path — and if the keys are missing at that point, it fails loudly with a
clear `TimetrackerApiError` rather than doing anything silently wrong.

## Scripts

| Command | What it does |
|---|---|
| `npm run start:dev` | Dev server with watch (port 3001) |
| `npm run build` / `start:prod` | Build / run production |
| `npm run db:up` / `db:down` | Postgres in Docker on/off |
| `npm run db:migrate` | Create + apply a migration (dev; also seeds) |
| `npm run db:deploy` | Apply migrations (prod) |
| `npm run db:seed` | Import/refresh seed data from TimeTracker |
| `npm run db:studio` | Prisma Studio (DB GUI) |
| `npm run lint` / `format` | ESLint / Prettier |
| `npm test` / `test:e2e` | Unit / e2e tests |

## Structure

```
prisma/
  schema.prisma      # data models (url is NOT here — Prisma 7)
  migrations/        # SQL migrations
  seed.ts            # thin CLI entrypoint (registered in prisma.config.ts); logic lives in src/prisma/seed/
prisma.config.ts     # Prisma CLI config (schema, migrations, datasource url, seed command)
src/
  main.ts            # bootstrap: /api prefix, /v1 versioning, CORS, pipes, Swagger
  app.module.ts      # root module — imports only, no controllers/services
  config/            # Joi env validation schema (infrastructure)
  prisma/            # PrismaModule + PrismaService, global (infrastructure)
    seed/            # seed orchestration logic + tests (see prisma/seed.ts)
  modules/           # feature modules — one folder per feature
    health/          # terminus health check
    users/           # example CRUD module (controller/service/dto/entities)
    contracts/       # cross-cutting interface contracts + stubs (backend substrate)
    registry/        # provider registry service/decorator (backend substrate)
    timetracker/     # TimeTracker external API client (seed-time only, no controller)
                     # unit tests live in __tests__/ inside each module
  generated/         # Prisma client (gitignored, generated by postinstall)
test/                # e2e
```

## Routes

- API: `http://localhost:3001/api/v1/...`
- Health: `GET /api/v1/health`
- Users CRUD: `POST|GET /api/v1/users`, `GET|PATCH|DELETE /api/v1/users/:id`
- Swagger: `http://localhost:3001/api/docs`

CORS is open for `http://localhost:4200` (frontend in `../frontend`).
